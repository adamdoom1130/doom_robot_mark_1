# 架构与通信协议

给固件开发者（也就是等硬件到货的你）看的规范。所有接口都由 DSH 插件 `dsh-esp32-robot` 提供，跑在 DSH 那个进程里。

---

## 一、一轮对话发生了什么

```
ESP32                          插件 (DSH 进程)                        DeepSeek
  │                                  │                                   │
  │ 录音到用户说完（本地 VAD/按钮）    │                                   │
  ├── POST /robot/api/turn ─────────►│                                   │
  │   Content-Type: octet-stream     │                                   │
  │   body = 16k s16le 裸 PCM        │ ① 补 WAV 头                        │
  │                                  ├── ② 语音识别 ──────────────────────►│ (本地或云)
  │                                  │◄── 文字 ───────────────────────────┤
  │                                  ├── ③ 送进 DSH 会话 ────────────────►│
  │                                  │      人格 + 上下文 + 工具           │
  │                                  │◄── 回复文字 / 工具调用 ─────────────┤
  │                                  │ ④ 工具调用 → 收进 actions 数组      │
  │                                  ├── ⑤ 第一句先合成                   │
  │◄── 200 + 一行 JSON 头 ───────────┤                                   │
  │◄── PCM 流（chunked，边合成边发）──┤                                   │
  │  播放，同时把 actions 入队        │                                   │
```

**为什么要先回 JSON 头再回音频**：设备一拿到头就知道"它说了什么、要做什么动作"，可以立刻把动作排进队列、把屏幕/表情亮起来，不用等音频播完。

## 二、接口一览

基址 = DSH 的地址（面板里「设备接入」那栏会显示完整地址），前缀统一是 `/robot`。

| 方法 | 路径 | 用途 | 鉴权 |
|---|---|---|---|
| POST | `/robot/api/turn` | **主接口**：音频/文字进，回复 + 音频出 | ✅ token |
| GET | `/robot/api/ping` | 开机握手、上报电量 | ✅ token |
| POST | `/robot/api/frame` | 上传一帧 JPEG | ✅ token |
| GET | `/robot/api/state` | 面板用：配置 + 运行状态 | ❌ 同源即可 |
| POST | `/robot/api/config` | 面板用：保存配置 | ❌ |
| GET | `/robot/api/voices` | 面板用：列出系统音色 | ❌ |
| POST | `/robot/api/face` | 面板用：手动换表情 | ❌ |
| GET | `/robot/api/search` | 面板用：检查联网搜索是否可用 | ❌ |
| GET | `/robot/sim` | 模拟器页面 | ❌ |

> 面板接口不校验 token，因为它们和网页同源，DSH 自己的登录态已经挡住了外部访问。设备接口必须带 token。

## 三、`POST /robot/api/turn` 详解

### 请求

四种 body 都支持，按 `Content-Type` 区分：

| Content-Type | body 内容 | 场景 |
|---|---|---|
| `application/octet-stream` | 16k s16le 单声道裸 PCM | **真机主用** |
| `audio/wav` | 带 RIFF 头的 WAV | 调试用（Audacity 导出） |
| `text/plain` | UTF-8 文字 | 不接麦克风先测大脑 |
| `application/json` | `{"text":"…","id":"robot-1","battery":87}` | 顺带上报设备状态 |

Query 参数（都可选）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `token` | — | 也可以放 `X-Robot-Token` 头或 `Authorization: Bearer` |
| `id` | `robot-1` | 设备名，多台设备时用来区分 |
| `rate` | 16000 | 上传音频的采样率（不是 16k 的话服务端会重采样） |
| `ch` | 1 | 声道数 |
| `fmt` | `stream` | 填 `json` 则返回 JSON + base64 音频（给浏览器/curl 用） |
| `timeout` | 90000 | 等大脑说话的毫秒数 |

### 响应（默认，设备用）

```
HTTP/1.1 200
Content-Type: application/vnd.robot.pcm
X-Robot-Rate: 16000
X-Robot-Format: s16le
Connection: close

{"ok":true,"reply":"你好呀，我叫小豆。","actions":[{"type":"move","direction":"forward","durationMs":600,"speed":36}],"heard":"你好呀","rate":16000,"format":"s16le","stream":true,"ms":{"asr":812,"total":2310}}
<PCM 原始字节…一直到连接关闭>
```

**解析规则**：读到第一个 `\n` 之前是 JSON 头，之后全是 PCM。就这么简单——不需要 chunked 解析器，不需要 Content-Length。

PCM 是 16kHz / 16bit 小端 / 单声道，`samples = bytes / 2`，时长 = `bytes / 32000` 秒。

### 响应（`?fmt=json`，不够快但省事）

```json
{"ok":true,"reply":"…","actions":[],"heard":"…","rate":16000,
 "audio":"<base64 的 PCM>","pcmBytes":48210,"stream":false}
```

### 失败

始终是 HTTP 200 + `ok:false`（设备端只需要判断 `ok`，不用处理状态码分支）：

```json
{"ok":false,"message":"DSH 里还没有装语音识别模型：…","heard":""}
```

```json
{"ok":false,"message":"上一轮还没说完，等一下"}
```

> 为什么不用 4xx/5xx：ESP32 的 HTTP 客户端处理状态码分支很啰嗦，统一 200 能省掉一堆错误处理。**唯一例外**是 token 不对，返回 401，方便调试时一眼看出来。

## 四、其他设备接口

### `GET /robot/api/ping`

```
GET /robot/api/ping?id=robot-1&battery=87&fw=0.1
→ {"ok":true,"name":"小豆","serverTime":1730000000000,"offlineMs":120000,"hasFrame":false,
   "face":{"emotion":"sleepy","intensity":0.6,"reason":"这个点了，有点困","activity":"idle","blink":true}}
```

开机先打一次，确认地址和 token 都对。
**之后每 10~30 秒再打一次**：返回值里的 `face` 就是「现在该显示什么表情」，空闲时靠它同步心情。

### `POST /robot/api/frame`

body = JPEG 原始字节。插件存到 `plugins-data/esp32-robot/frames/latest.jpg`，`robot_look` 工具读它。

建议：**只在需要时传**（模型调用 `robot_look` 之后，或每 5 秒一张），不要 30fps 往里推。

## 五、动作指令：其实只有「表情」

这台机器人没有轮子，所以 `actions` 里基本只有一类：换表情。

```json
{"type":"face","emotion":"happy","intensity":0.8}
{"type":"look"}
```

| 字段 | 说明 |
|---|---|
| `emotion` | `neutral / happy / excited / curious / thinking / listening / speaking / sleepy / sad / confused` |
| `intensity` | 0.2~1，表情的夸张程度（固件可以据此轻微放大眼型或动画幅度） |
| `type:"look"` | 表示模型刚「看」了一眼，固件可以让摄像头闪一下或眼睛睁大 |

**表情是怎么决定要不要变的**：

```
优先级：本地状态（录音中=聆听 / 播放中=说话）  >  actions 里的 face  >  ping 里的 face（心情）
```

也就是说：你说话时它一定是「聆听」的脸，它说话时一定是「说话」的脸（嘴会动），
没人理它的时候才显示心情。这样即使网络断了，脸部动画也不会僵。

**固件必须做的三件事**：
1. 收到 `face` 就切，并**保持**到下一次切换（不要 3 秒后自己变回去）
2. 每轮请求开始时清空上一轮残留的 actions
3. 播放音频期间强制用 `speaking`，播完回到心情

## 六、权限模型（"受限指令"到底限在哪）

三层，从上到下越来越硬：

```
第 1 层  面板开关        关掉 = 工具根本不注册，模型连这个能力的存在都不知道
                         （不是"拒绝了调用"，是"没有这个工具"）
第 2 层  参数截断        emotion 只认白名单里的十个，intensity 夹在 0.2~1，搜索条数有上限
第 3 层  前端兜底        就算跑到非法值，固件也只认白名单里的表情
```

第 1 层是最重要的：**能力不可见**比**能力被限制**安全得多。模型不会去尝试一个它看不到的工具。

| 工具 | 对应能力 | 关掉后果 |
|---|---|---|
| `robot_face` | 表情 / 心情 | 脸上永远是平静，也不能表达情绪 |
| `robot_search` | 联网搜索 | 只能用自己知道的，查不了新东西 |
| `robot_look` | 摄像头 | 看不见画面 |
| `robot_status` | 自检 | 永远可用，只读 |

> 心情模块（`mood.enabled`）是总闸：关掉之后即使 `permissions.face` 开着，`robot_face` 也不会挂载。

## 七、安全

| 项 | 做法 |
|---|---|
| 设备鉴权 | 每个设备一个 `rt_xxxx` 口令，面板里可以一键换 |
| 暴露面 | 只监听局域网（DSH 默认绑定本机或 LAN），**不要把 50006 端口映射到公网** |
| 最坏情况 | 口令泄漏 = 别人能让小车说话、动几下，仅此而已；碰不到电脑 |
| 插件边界 | 机器人会话的 preset 里**没有任何文件/命令/网络工具**，只有动作工具 |
| 配置隔离 | 机器人的数据在 `~/.dsh/plugins-data/esp32-robot/`，和你的代码会话完全分开 |

## 八、延迟预算与调优

| 环节 | 典型值 | 怎么降 |
|---|---|---|
| 录音结束后上传 | 0.1~0.5s | 局域网内直接用 HTTP，不要走 HTTPS 中转 |
| 语音识别 | 0.3~1.5s | 本地模型从 1.5s 降到 0.3s；或换小模型 |
| 大脑首字 | 0.5~2s | 用 `deepseek-flash` 而不是推理模型；人格里限制回复长度 |
| 语音合成首句 | 0.3~0.8s | 系统语音最快；自建 TTS 看机器性能 |
| 传输回设备 | 0.05~0.2s | 16k 单声道 32KB/s，局域网毫无压力 |

**两个最有效的优化**：
1. **按句流式**：插件已经实现（第一句合成完就发，后面的边合成边发），用户感知延迟 ≈ 第一句的耗时
2. **限制回复长度**：人格里写死"一次只说一两句"。这比任何工程优化都有效

## 九、命令行调试

不接硬件也能验证整条链路：

```powershell
# 1. 列音色
Invoke-RestMethod http://127.0.0.1:50006/robot/api/voices | ConvertTo-Json -Depth 4

# 2. 跑一轮，把音频存下来听
$tok = (Invoke-RestMethod http://127.0.0.1:50006/robot/api/state).config.device.token
Invoke-WebRequest -Method Post "http://127.0.0.1:50006/robot/api/turn?fmt=json" `
  -Headers @{ 'x-robot-token' = $tok } -ContentType 'text/plain' -Body '你好呀' `
  -OutFile r.json
$r = Get-Content r.json -Raw | ConvertFrom-Json
"$($r.reply)  /  $($r.pcmBytes) 字节"
```

> 端口以面板里显示的为准（DSH 每次启动可能换端口）。

## 十、以后要扩展时

| 想加的东西 | 协议层怎么改 |
|---|---|
| 唤醒词 | 固件本地做，不用改协议 |
| 打断（边播边听） | 改成 WebSocket 双向流；HTTP 做不到真正的双工 |
| 多设备 | `id` 已经留好了；插件里按 id 分别维护状态 |
| 舵机云台 | 加一个 `type:"servo"` 动作，其余不变 |
| 传感器上报 | `POST /robot/api/frame` 旁边加一个 `/api/sensors`，或者在 ping 的 query 里带 |
