# ESP32 小机器人 · 工作流程与阶段目标

> 一句话：一台能听、能说、能看的桌面小车，脑子在电脑上的 DeepSeek Harness 里，身上只有五官和手脚。
>
> 本文只回答两个问题：**这东西怎么一步步做出来**、**每一块各自要达成什么**。

---

## 一、先看懂整体

```
    ┌──────────────────────────── 小机器人（ESP32-S3） ───────────────────────────┐
    │                                                                            │
    │   INMP441 麦克风 ──I2S──►  录音 + 端点检测  ──┐                             │
    │                                              │  WiFi / HTTP（局域网）       │
    │   MAX98357A 功放 ◄──I2S── 播放 PCM  ◄────────┤                             │
    │                                              │                             │
    │   OV2640 摄像头 ──DVP──►  JPEG 抓帧 ─────────┤                             │
    │   SSD1306 小屏 ◄── I2C ── 表情（眼睛+嘴）◄───┘                             │
    │   18650 电池 ──► 降压 ──► 5V / 3.3V                                        │
    └──────────────────────────────────┬─────────────────────────────────────────┘
                                       │
                        ┌──────────────▼───────────────┐
                        │  电脑上的 DeepSeek Harness    │
                        │  ┌─────────────────────────┐  │
                        │  │ dsh-esp32-robot 插件     │  │
                        │  │  ① 网关（收音频/发音频） │  │
                        │  │  ② 耳朵：语音 → 文字     │  │
                        │  │  ③ 大脑：DSH 专用会话    │  │
                        │  │  ④ 嘴巴：文字 → 语音     │  │
                        │  │  ⑤ 手脚：受限动作工具     │  │
                        │  └─────────────────────────┘  │
                        └──────────────────────────────┘
```

三个关键决定，决定了后面所有工作：

| 决定 | 做法 | 为什么 |
|---|---|---|
| **脑子放在电脑上** | ESP32 只负责录音、播放、拍照、执行动作；思考全交给 DSH 里的 DeepSeek | ESP32 跑不动好模型；而且这样机器人能直接用上 DSH 的会话记忆、工具、人格配置 |
| **语音不走云厂商 SDK** | 电脑本地做语音识别和合成 | 免费、离线可用、延迟低、不用申请一堆 key |
| **动作走白名单** | 模型只能调用 5 个动作工具，且受时长/速度上限约束 | 它永远碰不到这台电脑，最坏情况也只是小车原地转圈 |

## 二、六条链路，各管一段

把系统拆成六条独立的链路，**每条都能单独做、单独测、单独坏**。这是整个项目能推进的关键。

| # | 链路 | 从哪到哪 | 你现在能测吗 |
|---|---|---|---|
| 1 | 听觉 | 麦克风 → 16k PCM → 文字 | ✅ 用电脑麦克风（模拟器页面） |
| 2 | 思考 | 文字 → DeepSeek → 回复文字 | ✅ 装好插件就能测 |
| 3 | 表达 | 回复文字 → 16k PCM → 喇叭 | ✅ 用电脑喇叭 |
| 4 | 视觉 | 摄像头 → JPEG → 模型「看到」 | ⏳ 等硬件；协议已定 |
| 5 | 表情 | 模型 → 情绪 → 屏幕上的眼睛和嘴 | ✅ 面板里就能点，实时预览 |
| 6 | 知识 | 模型 → 联网搜索 → 说结论 | ✅ 插件里已接好（要看 DSH 有没有搜索密钥） |
| 7 | 供电 | 电池 → 5V/3.3V → 续航 | ⏳ 等硬件；没有电机，方案很简单 |

**软件端的准备工作，本质就是把 1/2/3/5/6 这五条链路先用电脑跑通**，等板子到货只剩下 4/7。
这也是我做那个模拟器页面的原因——没有硬件也能把整条语音链路跑一遍。

## 三、阶段划分

一共 6 个阶段。每个阶段都写了「目标 / 要做什么 / 怎么算完成」，完成标准尽量写成**能看见的现象**，不是"感觉差不多了"。

### 阶段 0 · 软件骨架（现在，不需要任何硬件）

**目标**：在没有机器人的情况下，把「说话 → 思考 → 回话」完整跑通。

- [x] 写 DSH 插件 `dsh-esp32-robot`：网关、语音、大脑、动作工具、配置面板
- [x] 定通信协议（HTTP + 16k PCM 流）
- [x] 做模拟器页面：电脑麦克风当 INMP441，电脑喇叭当 MAX98357A
- [ ] 你重启 DSH → 设置 → 机器人 → 点「试一句」

**验收**：
- 面板里能看到机器人配置，改人格后下一句立刻变
- 模拟器页面说一句「你好」，2~5 秒内听到回答
- 回答内容符合人格设定（简短、口语、不念 Markdown）

**这一阶段最大的价值**：后面所有硬件问题都会被隔离在「传输层」，而不是「一说话就没反应，不知道是哪坏了」。

### 阶段 1 · 单点打样（硬件到货后第 1~3 天）

**目标**：每个器件单独能用，不做整合。

| 器件 | 要验证的事 | 完成标准 |
|---|---|---|
| 开发板 | 能烧录、能连 WiFi、串口能打印 | 串口每秒打印一次 IP |
| INMP441 | I2S 录音 | 录 3 秒，存成 WAV 在电脑上能听清自己说话 |
| MAX98357A | I2S 播放 | 播放一段正弦波，喇叭有干净的声音，无爆音 |
| OV2640 | 拍照 | 抓到一张 320×240 JPEG，电脑上能打开 |
| 电机 + 驱动 | 正反转 | 前进 1 秒、后退 1 秒、左转、右转 |
| 电池 | 供电 | 拔掉 USB 仍能跑，电压稳定，模块不重启 |

**验收**：六个器件**全部单独通过**才进入阶段 2。任何一个没通就整合，最后一定找不到问题在哪。

> 这一步最常见的坑：I2S 麦克风和功放抢时钟、电机一转板子就重启（电源）、摄像头和 PSRAM 抢引脚。详见 `03-固件与硬件.md`。

### 阶段 2 · 打通一条语音（第 4~6 天）

**目标**：真机说一句话，真机喇叭听到回答。此时还不移动。

- 固件实现：按住按钮（或 VAD 检测）录音 → 攒够 2~5 秒 → POST 到 `/robot/api/turn` → 读回「一行 JSON + PCM」→ 边收边播
- 电脑端不需要改任何东西（阶段 0 已经验证过）

**验收**：
- 说「你好呀」→ 喇叭回话，延迟可接受（目标 < 4 秒）
- 拔掉网线 → 固件给出明确提示（不是死机）
- 连续说 10 句不崩

**这里要开始盯的指标**：端到端延迟。拆开看是四段：

```
录音结束 → 上传      0.1~0.5s
识别                 0.3~1.5s   ← 最大变量
DeepSeek 首字        0.5~2s     ← 第二变量
语音合成首句         0.3~0.8s
─────────────────────────────────
合计                 1.2~4.8s
```

超过 5 秒就要动手：换更快的识别模型、开流式合成（插件已经按句流式发）、或者限制回复长度。

### 阶段 3 · 让它的脸活起来（第 7~9 天）

**目标**：屏幕上那张脸跟着情绪走，而且**只在允许的范围内**。

这台机器人没有轮子，所以「行动」全部发生在屏幕上：

- 固件用 U8g2 驱动 72×40 的 SSD1306，照 `plugin/lib/face.js` 的表情表画眼睛和嘴
- 收到 `actions` 里的 `{type:"face"}` 就切表情，**保持**到下一次切换
- 本地状态优先：录音时=聆听、播放时=说话（嘴会动）、空闲时=心情
- 眨眼：每 3~6 秒压一次眼，只在睁眼的表情上眨
- 电量低于 15% 自动切 `sleepy`

**验收**：
- 面板里点「开心」→ 屏幕上真的笑，眼睛弯成月牙
- 跟它说「我升职了」→ 它自己切到开心（面板「最近一轮」里能看到 `{"type":"face"}`）
- 关掉心情模块 → 屏幕固定平静，模型不再提表情
- 拔网线 → 脸不僵（本地状态机还在跑）

### 阶段 3.5 · 让它能查（第 9~10 天）

**目标**：问它新东西，它会去查，然后**用自己的话**说结论。

- 插件侧已经做完（`robot_search`），固件不用管
- 要做的是：在 DSH 里把搜索密钥配上，然后点面板的「检查联网」确认
- 没配也能用——它会老实说查不到，不会编

**验收**：
- 问「今天有什么科技新闻」→ 它说得出具体内容，而不是「我查到了但读不出来」
- 问一个查不到的 → 它说查不到，不瞎编

### 阶段 4 · 让它看见（第 10~12 天）

**目标**：摄像头画面能进到模型上下文里。

这一阶段要先做一个决定：**DeepSeek 的对话模型能不能直接吃图**。

- 能 → 每轮带一张压缩后的小图（320×240，JPEG 质量 50，约 8~15KB）
- 不能 → 走「看图模型」旁路：插件把图交给一个支持视觉的模型，返回一句描述，再喂给主模型

插件里已经留好了 `robot_look` 工具和 `/robot/api/frame` 上传接口，两种做法都不用改协议。

**验收**：
- 把一只杯子放在它面前，问「你看到什么」→ 回答里有"杯子"
- 遮住摄像头 → 明确说"看不见"，不编造

### 阶段 5 · 变成一个成品（第 13 天以后）

- 外壳、云台、走线、配重
- 续航实测（目标：连续对话 2 小时以上）
- 唤醒词（可选）：本地关键词检测，省电、也不用一直传音频
- 断网降级：连不上就本地回一句"我暂时听不懂"

**验收**：放在桌上，家人不用看说明书就会用。

## 四、每个部件的工作目标

### 1. 麦克风（INMP441）

| 项目 | 要求 |
|---|---|
| 职责 | 把声音变成 16kHz / 16bit / 单声道数字音频 |
| 关键参数 | I2S，24bit 数据在 32bit 帧里（左对齐），**L/R 接地 = 左声道** |
| 工作目标 | 1 米内正常说话能稳定识别；安静时底噪不触发录音 |
| 失败表现 | 全是电流声 → 时钟或电源问题；声音断续 → DMA 缓冲太小 |

> 采 16k 就够。不要采 44.1k：识别模型会重采样，白白多 3 倍流量和 CPU。

### 2. 喇叭（MAX98357A）

| 项目 | 要求 |
|---|---|
| 职责 | 把 16k PCM 直接推给喇叭 |
| 关键参数 | I2S，默认增益 9dB；SD 脚接法决定声道和关断 |
| 工作目标 | 3 米内听清；无爆音、无"咔哒"声 |
| 失败表现 | 有节奏的咔哒声 → 缓冲区欠载；只有一边响 → SD 脚接错 |

> **引脚是最大的瓶颈**：摄像头一个人吃掉 12 根，PSRAM 又锁死 5 根，真正自由的只有 11 个。
> 省引脚的两个办法：电机用 4 线接法（PWM 直接打在 IN1/IN2 上），以及 I2S 收发共用一组时钟。
> 完整分配见 `03-固件与硬件.md`。

### 3. 摄像头（OV2640）

| 项目 | 要求 |
|---|---|
| 职责 | 按需抓一帧 JPEG |
| 关键参数 | DVP 并口 12 根线，XCLK 20MHz，QVGA/240×320 |
| 工作目标 | 抓一帧 < 300ms，JPEG < 20KB |
| 失败表现 | 花屏 → PCLK 太快或排线松动；全黑 → XCLK/PWDN |

> 摄像头是**最吃引脚**的器件（12 根）。先把它定下来，剩下的引脚再分给 I2S 和电机。

### 4. 大脑（DSH 里的 DeepSeek 会话）

| 项目 | 要求 |
|---|---|
| 职责 | 理解、决定怎么说、决定要不要换表情 / 要不要查资料 |
| 关键参数 | 独立会话 + 独立 preset，不和你写代码的会话混在一起 |
| 工作目标 | 首字 < 1.5s；回复 1~2 句；不会突然开始念代码 |
| 失败表现 | 回复很长 → 人格里没限制长度；乱调工具 → 权限没配好 |

> 它的人格、模型、权限全部在 DSH 面板里改，改完下一句生效，不用重新烧固件。

### 5. 脸（0.36 寸 OLED）

| 项目 | 要求 |
|---|---|
| 职责 | 把 `face` 指令变成屏幕上的眼睛和嘴 |
| 关键参数 | SSD1306 72×40，I2C 400kHz，全屏刷新 5~10ms |
| 工作目标 | 十个表情都对得上；切换 < 100ms；眨眼不卡顿 |
| 失败表现 | 花屏 → I2C 地址或速率；表情错位 → 坐标没按 72×40 算 |

**三道保险，缺一不可**：
1. 模型层：`emotion` 只认白名单里的十个，`intensity` 夹在 0.2~1
2. 服务层：心情模块关掉时，`robot_face` 工具**根本不注册**
3. 固件层：认不出的 emotion 一律退回 `neutral`，不会画出一团乱码

### 6. 供电

| 项目 | 要求 |
|---|---|
| 职责 | 给功放 5V、主控 3.3V、屏幕 3.3V |
| 关键参数 | 单节 18650 + 升压/降压到 5V，功放侧并 470µF |
| 工作目标 | 连续对话 4 小时以上；声音大时不重启 |
| 失败表现 | 一拧电机就重启 → 电池内阻大 / 没加电容 / 共地没做好 |

## 五、软件端现在就能做的清单

按顺序做，每一步都有明确的"做完了"：

1. **左侧栏点「机器人」** → 面板出现（说明插件加载成功）
2. 点「试一句」→ 听到它说话（说明大脑 + 嘴巴通了）
3. 改人格：把名字改成你想要的，加一句口头禅 → 再点「试一句」，确认立刻变化
4. 打开模拟器（面板里那个按钮）→ 对着电脑麦克风说话 → 听到回答（说明听觉也通了）
5. 在面板「对它说」里打「换个开心的表情」→ 「最近一轮」里应该出现 `actions: [{"type":"face"...}]`
6. 到面板里**关掉**心情模块 → 再说一次 → 它不再提表情，按钮也变灰
7. 点「检查联网」→ 看这台机器能不能真的搜（不能也没关系，它会老实说查不到）
8. 换模型：面板里填 `deepseek-chat` → 对比回答质量与速度
9. 打开 `%USERPROFILE%\.dsh\plugins-data\esp32-robot\config.json`，看一遍配置长什么样（以后出问题先看这个文件）
10. 用 `curl` 直接打接口，确认不依赖浏览器也能跑（命令见 `02-架构与协议.md`）
11. 到 `03-固件与硬件.md` 里把引脚表抄成自己的实际接线图，**动手前先对一遍**

做完 1~7，软件端就算准备完了。剩下的都是硬件到了以后的事。

## 六、风险清单（按发生概率排序）

| 风险 | 概率 | 后果 | 提前怎么办 |
|---|---|---|---|
| 电源扛不住功放峰值 | 中 | 声音一大就重启 | 功放侧并 470µF；先做阶段 1 的电池测试 |
| 引脚不够用 | 高 | 要重新分配或加扩展芯片 | 摄像头 12 根先占位；I2S 收发共用时钟；电机用 I2C 驱动（PCA9685）兜底 |
| 语音识别不准 | 中 | 一句话要重复三次 | 先做"按住说话"（明确起止），别一上来做唤醒词 |
| 延迟太长 | 中 | 用起来很别扭 | 插件已按句流式发声；再不行就换识别模型、限制回复长度 |
| 模型乱动 | 中 | 小车跑飞 | 三道保险；权限默认只开"说"，动起来要手动开 |
| 摄像头和 PSRAM 抢引脚 | 中 | 花屏、随机崩溃 | N16R8 的 GPIO33~37 是八线 PSRAM，**绝对不能用** |
| 板子型号的摄像头引脚和文档不一致 | 高 | 摄像头不工作 | 到货先用例程验证引脚表，再写自己代码 |

## 七、时间预期

| 阶段 | 内容 | 日历时间 | 每天投入 |
|---|---|---|---|
| 0 | 软件骨架 | 已完成 | — |
| 1 | 单点打样 | 3 天 | 2~3 小时 |
| 2 | 语音闭环 | 3 天 | 2~3 小时 |
| 3 | 动作闭环 | 3 天 | 2~3 小时 |
| 4 | 视觉 | 3 天 | 2 小时 |
| 5 | 成品化 | 1~2 周 | 弹性 |

**第一个能用的小机器人：大约两周。** 真正耗时的从来不是写代码，是查线、查电源、查为什么这个模块单独能用合起来就不能用。
